Correctness

An Aho–Corasick automaton is easy to get almost right. A missing dictionary-suffix link loses nested matches and nothing else; a failure link computed from the wrong node loses matches only when two patterns share a particular suffix; an off-by-one in the offset arithmetic is invisible until someone redacts a secret and leaves its last byte behind. All three survive a test suite of hand-written examples, because hand-written examples test the cases the author already thought of.

So the primary check here is not an example. It is an oracle: a second, obviously-correct implementation, and a generator that keeps proposing inputs on which the two must agree.

The oracle

The reference implementation is a naive per-pattern scan — for each pattern, try it at every offset. It is quadratic and useless in production, which is precisely why it is trustworthy: there is no automaton, no failure link and no shared state to get wrong. 

(* test/test_aho_corasick.ml *)
let naive patterns text =
  List.concat
    (List.mapi
       (fun pi p ->
         let lp = String.length p and n = String.length text in
         let acc = ref [] in
         for i = 0 to n - lp do
           if String.sub text i lp = p then acc := m pi i (i + lp) :: !acc
         done;
         List.rev !acc)
       patterns)

QCheck then generates pattern sets and inputs and asserts that find_all and naive return the same matches.

The six properties, run on every CI run
Property Cases Asserts
find_all = naive scan 1000 The same set of matches as the reference implementation.
chunked streaming = whole input 500 Stream.feed over random chunks, concatenated, equals find_all of the whole input as a list, in order.
chunked non-overlapping = greedy earliest-end 500 Stream.feed_nonoverlapping equals a separate greedy walk over find_all's ordering — the rule written out, rather than the automaton's shortcut for it.
chunked leftmost-longest = whole input 500 Stream.Leftmost_longest feeds plus flush equal find_leftmost_longest of the whole input.
chunked replace = replace_all 500 Stream.Replace pieces, concatenated, equal replace_all — with replacements that shrink, grow and delete, since a length-preserving one would hide an offset bug.
leftmost-longest selection 500 The selection is ordered and non-overlapping, and every selected match is a real match.

The chunking generator is the interesting one: it splits each input at a random list of sizes, with whatever remains becoming a final chunk, so empty chunks and empty tails are exercised too. Four of the six properties run through it, one per streaming mode, and each is pinned to the whole-input function it claims to reproduce.

Why the generators look so small

Patterns are 1 to 3 bytes drawn from {a, b, c}, there are 1 to 5 of them, and inputs are up to 60 bytes from the same three letters. That looks like weak testing and is the opposite of it. A three-letter alphabet with short patterns maximises the density of the things that break Aho–Corasick implementations: patterns that are suffixes of other patterns, patterns that overlap themselves, several patterns ending at the same offset, and constant traffic down the failure links. Over a realistic alphabet, a random 60-byte input would contain almost no matches at all, and a thousand such cases would test nothing.

When a property does fail, QCheck shrinks the counterexample before reporting it, so what lands in the CI log is a minimal pattern set and input rather than the 60-byte case that happened to trip it.

The worked examples

Thirteen Alcotest cases pin down the behaviour the oracle cannot see, starting with the canonical pattern set from the original 1975 paper.

What each example is for
Group Case Pins down
classic ushers The canonical pattern set, and the exact report order.
overlapping Self-overlap, and nesting at a single end offset.
duplicate patterns Both indices reported, ascending.
empty inputs Empty pattern list matches nothing; empty pattern raises.
pattern accessors pattern_count, pattern, and the out-of-bounds exception.
ignore_case ASCII folding on, and case sensitivity when off.
leftmost-longest selection Leftmost beats longest; longest breaks ties at one start.
replace_all Non-overlapping replacement, and untouched input when nothing matches.
streaming find_iter Identical to find_all, and lazy enough to stop early.
chunk boundary A match spanning two feeds, with absolute offsets, and pos.
non-overlapping The restart after a match, carried across a boundary, and Rust's Samwise case.
leftmost-longest A match held back until it can be decided — and not held back when it cannot be outranked.
replace The longest match winning across a chunk boundary, and pieces that concatenate to replace_all.

The report order is the part carried entirely by these examples. The oracle compares match sets — both sides are sorted before comparison, because the naive scan produces matches grouped by pattern rather than by offset. The chunking properties compare ordered lists, but against find_all itself, so both sides would move together. A change to the ordering rules would slip past all 3500 generated cases and be caught by ushers and overlapping instead.

Running it yourself

opam install . --deps-only --with-test
dune build @all
dune runtest

That is what CI does, on ubuntu-latest, against OCaml 4.14 and 5.4, for every push to main and every pull request. There is no separate long-running suite: the 3500 generated cases run in the ordinary test job.

What none of this covers

Stated plainly, because a page about correctness that only lists strengths is marketing.

No cross-implementation differential test
Nothing runs this library against the Rust or Python implementations. The compatibility claims are a reading of published behaviour, not a test result. The conformance vectors are there so anyone can close that gap from the outside.
Leftmost-longest maximality is not asserted
The property test checks that the selection is ordered, non-overlapping and made of real matches. It does not assert that each selected match is the longest one starting at that offset, nor that no selectable match was skipped. Those follow from the selection rule and are covered by the worked examples, but they are not generated over.
Ordering is not generated over independently
The oracle normalises before comparing. The four chunking properties do compare lists in order, but both sides come from this implementation, so they pin streaming to find_all rather than pinning find_all's order to anything outside it. That still rests on the hand-written cases.
No adversarial pattern sets
The generators produce small, friendly pattern sets. Nothing exercises tens of thousands of patterns, deep tries, patterns near the length of the input, or memory behaviour under load.
No fuzzing, no benchmarks, no audit
There is no AFL or Crowbar target, no published performance figures, and no external review. This is a small pure-OCaml library at 0.1.0.
Not constant-time
Scan time depends on the input and on how many matches it contains. Do not use this to compare secrets.

If you find a disagreement

A pattern set, an input, what you got and what you expected is enough to reproduce anything on this site — every claim here is a function of those two inputs. Open an issue. A case that breaks the oracle is a bug; a case where another implementation disagrees but the oracle does not is a semantics difference, and belongs on the compatibility page.
