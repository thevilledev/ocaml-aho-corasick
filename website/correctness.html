Correctness

An Aho–Corasick automaton is easy to get almost right. A missing dictionary-suffix link loses nested matches and nothing else; a failure link computed from the wrong node loses matches only when two patterns share a particular suffix; an off-by-one in the offset arithmetic is invisible until someone redacts a secret and leaves its last byte behind. All three survive a test suite of hand-written examples, because hand-written examples test the cases the author already thought of.

So the primary check here is not an example. It is an oracle: a second, obviously-correct implementation, and a generator that keeps proposing inputs on which the two must agree.

The oracle

The reference implementation is a naive per-pattern scan — for each pattern, try it at every offset. It is quadratic and useless in production, which is precisely why it is trustworthy: there is no automaton, no failure link and no shared state to get wrong. 

(* test/test_aho_corasick.ml *)
let naive patterns text =
  List.concat
    (List.mapi
       (fun pi p ->
         let lp = String.length p and n = String.length text in
         let acc = ref [] in
         for i = 0 to n - lp do
           if String.sub text i lp = p then acc := m pi i (i + lp) :: !acc
         done;
         List.rev !acc)
       patterns)

QCheck then generates pattern sets and inputs and asserts that find_all and naive return the same matches.

The six properties, run on every CI run
Property Cases Asserts
find_all = naive scan 1000 The same set of matches as the reference implementation.
chunked streaming = whole input 500 Feeding the input in random chunks and concatenating the results gives exactly find_all of the whole input, as a list, in order.
chunked non-overlapping = greedy earliest-end 500 Stream.feed_nonoverlapping over random chunks equals the greedy earliest-end selection computed from find_all.
chunked leftmost-longest = whole input 500 Stream.Leftmost_longest over random chunks, plus flush, equals find_leftmost_longest.
chunked replace = replace_all 500 Stream.Replace over random chunks, with shrinking, growing and deleting replacements, equals replace_all.
leftmost-longest selection 500 The selection is ordered and non-overlapping, and every selected match is a real match.

Why the generators look so small

Patterns are 1 to 3 bytes drawn from {a, b, c}, there are 1 to 5 of them, and inputs are up to 60 bytes from the same three letters. That looks like weak testing and is the opposite of it. A three-letter alphabet with short patterns maximises the density of the things that break Aho–Corasick implementations: patterns that are suffixes of other patterns, patterns that overlap themselves, several patterns ending at the same offset, and constant traffic down the failure links. Over a realistic alphabet, a random 60-byte input would contain almost no matches at all, and a thousand such cases would test nothing.

When a property does fail, QCheck shrinks the counterexample before reporting it, so what lands in the CI log is a minimal pattern set and input rather than the 60-byte case that happened to trip it.

The worked examples

Thirteen Alcotest cases pin down the behaviour the oracle cannot see, starting with the canonical pattern set from the original 1975 paper.

What each example is for
Group Case Pins down
classic ushers The canonical pattern set, and the exact report order.
overlapping Self-overlap, and nesting at a single end offset.
duplicate patterns Both indices reported, ascending.
empty inputs Empty pattern list matches nothing; empty pattern raises.
pattern accessors pattern_count, pattern, and the out-of-bounds exception.
ignore_case ASCII folding on, and case sensitivity when off.
leftmost-longest selection Leftmost beats longest; longest breaks ties at one start.
replace_all Non-overlapping replacement, and untouched input when nothing matches.
streaming find_iter Identical to find_all, and lazy enough to stop early.
chunk boundary A match spanning two feeds, with absolute offsets, and pos.
non-overlapping Scanning restarts after a match, across a chunk boundary; earliest end wins on Samwise.
leftmost-longest A shorter match is held back while a longer one may still form, and released by flush; matches nothing can outrank are not held back.
replace Streamed replacement equals replace_all, with the longest match winning across a chunk boundary.

The report order is the part carried entirely by these examples. The oracle compares match sets — both sides are sorted before comparison, because the naive scan produces matches grouped by pattern rather than by offset — so a change to the ordering rules would slip past all 1000 generated cases and be caught by ushers and overlapping instead.

Other implementations' vectors

A second Alcotest suite, test/test_conformance.ml, runs the test vectors of other implementations through this library: the Rust aho-corasick crate's own tables (its BASICS, STANDARD, NON_OVERLAPPING, OVERLAPPING, LEFTMOST, LEFTMOST_LONGEST, case-insensitive and regression tables, and its standalone regression tests), the vectors daachorse adds to the same tables, pyahocorasick's iter_long regression cases, the examples in the Rust crate's API documentation, and the vectors on the compatibility page. Each vector is run through every function here that promises the same semantics — whole-input, lazy, and streamed with 1-byte and 3-byte chunks — and through replace_all and Stream.Replace where the semantics are leftmost-longest. Vectors containing the empty pattern, which build rejects, and the leftmost-first tables are the only ones left out.

The differential test

Vectors are still cases someone thought of. The differential harness in compat/ generates 20 000 pattern-set, input and chunking combinations from a fixed seed, runs them through this library, the Rust crate, pyahocorasick and ahocorasick_rs, and compares the outputs as strings: same pattern indices, same offsets, same order. It is a CI job, and a change that makes this library disagree with the Rust crate fails the build.

Running it yourself

opam install . --deps-only --with-test
dune build @all
dune runtest
./compat/run.sh      # the differential test; needs cargo and pyahocorasick

That is what CI does, on ubuntu-latest, against OCaml 4.14 and 5.4, for every push to main and every pull request: the 3500 generated property cases and the ported vectors run in the ordinary test job, and the differential test in a job of its own.

What none of this covers

Stated plainly, because a page about correctness that only lists strengths is marketing.

The differential test covers three other implementations
The Rust crate, pyahocorasick and ahocorasick_rs, and the last of those is the Rust crate underneath. Nothing runs this library against Hyperscan or the Go and Java implementations; the conformance vectors and the harness's case format are there so anyone can add one.
Leftmost-longest maximality is not asserted by the in-repository oracle
The property test checks that the selection is ordered, non-overlapping and made of real matches. It does not assert that each selected match is the longest one starting at that offset, nor that no selectable match was skipped. Those follow from the selection rule; the differential test checks them against the Rust crate's leftmost-longest search, and the ported vectors check them by example.
Ordering is not generated over by the in-repository oracle
The oracle normalises before comparing. Ordering rests on the hand-written cases and on the differential test, which compares order too.
Small adversarial pattern sets only
The generators produce small pattern sets. The benchmarks exercise 15 000-word dictionaries and pathological overlap, but only for throughput and match counts; nothing generates over large pattern sets, patterns near the length of the input, or memory behaviour under load.
No fuzzing, no audit
There is no AFL or Crowbar target and no external review. This is a small pure-OCaml library at 0.1.0.
Not constant-time
Scan time depends on the input and on how many matches it contains. Do not use this to compare secrets.

If you find a disagreement

A pattern set, an input, what you got and what you expected is enough to reproduce anything on this site — every claim here is a function of those two inputs. Open an issue. A case that breaks the oracle is a bug; a case where another implementation disagrees but the oracle does not is a semantics difference, and belongs on the compatibility page.
