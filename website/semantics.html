Match semantics

This page is the specification. Everything stated here is a promise the library keeps and the test suite exercises — including the ordering rules, which are the part most libraries leave unsaid and most consumers quietly depend on. Before 1.0 any of it can still change, but not silently: a change to the rules below is a CHANGES.md entry.

Throughout, s is the input, |s| its length in bytes, and s[a..b) the bytes at offsets a to b excluding b.

Offsets are half-open byte offsets

A match_ is { pattern; start; stop }. start is the offset of the first matched byte; stop is the offset one past the last matched byte. The matched text is therefore String.sub s m.start (m.stop - m.start), the length is m.stop - m.start, and a match at the very end of the input has stop = |s|.

The numbers sit on the boundaries between bytes, not on the bytes. This is the same convention as OCaml's own String.sub, as Rust ranges, and as the Span of the Rust aho-corasick crate. It is not the convention of every library in this space; see offset conventions.

What counts as an occurrence

For a pattern p at index i, an occurrence in s is a pair (a, b) with b - a = |p|, 0 ≤ a, b ≤ |s|, and s[a..b) = p. With ~ignore_case:true, that last equality is taken after ASCII folding of both sides.

find_all returns exactly the occurrences of every pattern: never a substring that is not an occurrence, and never fewer than all of them. Occurrences overlap freely, nest freely, and a pattern that is a substring of another is reported alongside it.

Every occurrence, including the ones people forget
Patterns Input find_all Why
["aa"] "aaaa" 0..2, 1..3, 2..4 A pattern overlaps itself.
["a"; "ab"; "abc"] "abca" 0..1, 0..2, 0..3, 3..4 Nested patterns all count.
["x"; "x"] "ax" 1..2 as pattern 0, 1..2 as pattern 1 Duplicates each get their index.
["he"; "she"; "his"; "hers"] "ushers" she 1..4, he 2..4, hers 2..6 Two patterns end at offset 4.

The order is total and specified

find_all returns matches sorted by:

  1. stop, ascending — the position at which the match was recognised;
  2. then length (stop - start), descending — longest first among matches ending together;
  3. then pattern, ascending — which can only break a tie between duplicate patterns.

The three rules together are a total order: no two distinct elements of the result compare equal, so the list is fully determined by the pattern set and the input. This falls out of how the automaton works — a match is emitted the moment its last byte is read, and the dictionary-suffix chain walks from the longest match ending there to the shortest — but it is a promise, not an accident.

find_iter yields the same matches in the same order, one at a time. Stream.feed yields them in the same order too; concatenating the lists from a sequence of feeds gives exactly find_all of the concatenated input, element for element.

Leftmost-longest selection

find_leftmost_longest picks a non-overlapping subset. The rule, stated as the algorithm it is:

  1. Take all occurrences.
  2. Order them by start ascending, then length descending, then pattern index ascending.
  3. Walk that order with a cursor starting at 0. Take a match if its start is at or after the cursor, and move the cursor to its stop; otherwise discard it.

The result is non-overlapping and ordered by start ascending. Equivalently: repeatedly take the leftmost match that starts at or after the end of the previous one, preferring the longest when several start together. This is the POSIX leftmost-longest rule, the same one a POSIX regex engine applies to an alternation.

Leftmost beats longest
Patterns Input Selected Dropped, and why
["Sam"; "Samwise"] "Samwise" Samwise 0..7 Sam 0..3 — same start, shorter.
["ab"; "bc"] "abc" ab 0..2 bc 1..3 — starts later, overlaps.
["b"; "ba"] "aba" ba 1..3 b 1..2 — same start, shorter.
["he"; "she"; "his"; "hers"] "ushers" she 1..4, and nothing else he 2..4 and hers 2..6 both start inside she.

That last row is worth staring at. hers is the longest occurrence in ushers, and leftmost-longest does not select it, because a match starting one byte earlier was taken first. Leftmost is decided before longest; only among matches that start at the same offset does length break the tie.

Replacement

replace_all t ~f s replaces each find_leftmost_longest match m with f m, leaving the bytes between matches untouched, and never rescans the replacement text. So replace_all with ~f:(fun m -> String.sub s m.start (m.stop - m.start)) reproduces s exactly, and replace_all (build ["aa"]) ~f:(fun _ -> "X") "aaaa" is "XX", not "XXX" — the overlapping occurrence at 1..3 is not selected.

Membership

mem t s is true if and only if find_all t s is non-empty. It stops at the first byte that completes any pattern, so it is the right call when you only need a yes or no.

Case folding is ASCII only

~ignore_case:true maps bytes 0x41 to 0x5A (A to Z) to 0x61 to 0x7A, in the patterns at build time and in the input during the scan. No other byte is touched.

  • build ~ignore_case:true ["Rust"] matches rust, RUST and rUsT.
  • It does not match É against é, or fold any byte above 0x7F. There is no Unicode case mapping here, and there is no locale.
  • Folding is length-preserving, so stop - start is still the pattern's byte length, and offsets still index the original, unfolded input.
  • pattern t i returns the pattern as you wrote it, not the folded form.

Bytes, not characters

Every byte value from 0x00 to 0xFF is ordinary, NUL included; patterns and inputs are arbitrary OCaml strings and nothing is treated as a terminator. UTF-8 text works as byte matching — a UTF-8 pattern finds UTF-8 occurrences — but the offsets are byte offsets. Searching "café au lait" for "é" reports 3..5, because é is two bytes; there is no character index 3..4 anywhere in the API.

A pattern that is not valid UTF-8 will never split a character in valid UTF-8 input, since UTF-8 is self-synchronising, but the library does not check or rely on this. If you need character offsets, convert them above this layer.

Edge cases

Fully specified, not accidents of implementation
Empty pattern build raises Invalid_argument "Aho_corasick.build: empty pattern". An empty pattern would match at every offset, which is never what a scanner wants.
Empty pattern list Legal. The automaton matches nothing; mem is always false.
Empty input No matches. Every match needs at least one byte.
Duplicate patterns Allowed. Each occurrence is reported once per duplicate index, in ascending index order.
Pattern longer than the input No match, no error.
pattern t i out of bounds Raises Invalid_argument "Aho_corasick.pattern: index out of bounds".

Standard, non-overlapping

Stream.feed_nonoverlapping reports a non-overlapping subset by a different rule from leftmost-longest, and the difference is the single most common source of surprise when comparing two Aho—Corasick libraries. The rule:

  1. Scan left to right. At every offset where one or more matches end, report the longest of them.
  2. Restart the automaton immediately after that match, so nothing overlapping it can be reported.

Equivalently: walk find_all in its own order — end offset ascending, longest first — and greedily take every match that starts at or after the end of the last one taken. The earliest ending match wins, which is not the same as the leftmost-longest one.

Where the two non-overlapping rules part company
Patterns Input feed_nonoverlapping find_leftmost_longest
["Sam"; "Samwise"] "Samwise" Sam 0..3 Samwise 0..7
["a"; "ab"; "abc"] "abca" a 0..1, a 3..4 abc 0..3, a 3..4
["b"; "ba"] "aba" b 1..2 ba 1..3
["aa"] "aaaa" aa 0..2, aa 2..4 aa 0..2, aa 2..4

These are the semantics of the Rust crate's stream_find_iter under MatchKind::Standard. Neither rule is more correct than the other; they answer different questions. Use feed_nonoverlapping when you want every match the moment it completes and never want to wait, and leftmost-longest when you are going to cut or substitute and the longest match must win.

There is no whole-input counterpart of this rule in the API. If you want it over a string, feed the string as one chunk.

Streaming

All three semantics stream, and so does replacement. Every one of them counts offsets from the start of the stream rather than the start of the chunk, so a match that begins in one chunk and ends in a later one carries the start it would have had in a single-pass scan.

The three streaming modes
Mode Equals, for any chunking Latency
Stream.feed find_all of the whole input, in the same order none; nothing to flush
Stream.feed_nonoverlapping the earliest-end rule applied to the whole input none; nothing to flush
Stream.Leftmost_longest find_leftmost_longest of the whole input, once flush has been called bounded by the longest pattern
Stream.Replace replace_all of the whole input, concatenating the pieces bounded by the longest pattern

For the first two the guarantee is an exact equality with no end-of-stream call at all: every match is reported as soon as its final byte is seen, so a stream that is cut short has still reported everything that actually matched. Feed any one stream exclusively with feed or exclusively with feed_nonoverlapping — they share a state type, but the restart-after-match discipline only makes sense applied to the whole stream.

Bounded lookahead

Leftmost-longest cannot always decide a match the moment it ends, because a longer match starting at or before it may still be in progress. It can always decide it eventually, and the bound is exact: no match is longer than the longest pattern, so once scanning has passed one longest-pattern length beyond a candidate's start, nothing that could outrank it remains possible. A match is therefore reported by the first Leftmost_longest.feed whose input reaches that point, and the state holds at most that window of candidates.

So with ["b"; "ba"], the longest pattern is two bytes: 

module L = Aho_corasick.Stream.Leftmost_longest

let st = L.start t               (* patterns ["b"; "ba"] *)
let st, ms1 = L.feed t st "ab"   (* [] : b at 1..2 may still grow into ba *)
let st, ms2 = L.feed t st "a"    (* ba 1..3, now decided *)
let rest = L.flush st            (* [] *)

Nothing is held back that does not need to be. With ["a"], no match can ever be outranked, and L.feed t (L.start t) "aaa" returns all three matches immediately.

flush ends the stream and returns whatever the lookahead was still holding; do not feed a flushed state again. Stream.Replace works the same way on bytes rather than matches: feed returns the next piece of output, holding back only input that could still turn out to be inside a match, and the concatenation of every piece with flush's equals replace_all of the concatenated input.

What is deliberately not specified

The automaton's shape
Node numbering, the transition representation and the internal link arrays are private. Only the observable matches are promised.
Physical sharing
Whether two equal match_ values are physically equal, or whether pattern t i returns a shared string, is not promised. Compare structurally.
Timing
Nothing here is constant-time or side-channel resistant. Scan time depends on the input and on how many matches it contains. Do not use this to compare secrets.
