The API

One module, Aho_corasick: eight functions over whole inputs, and a Stream submodule offering the same searches over chunks. What each one reports is on the semantics page; this page is about the shape of the interface and what it costs.

Types

type t
(* A compiled automaton. Immutable and safe to share across threads. *)

type match_ = {
  pattern : int;  (* index of the pattern in the list given to build *)
  start : int;    (* byte offset of the first matched byte *)
  stop : int;     (* byte offset one past the last matched byte *)
}

A match_ carries an index rather than the matched string, so a scan over a large input allocates one small record per match and copies no bytes. Recover the text with String.sub s m.start (m.stop - m.start), or the pattern with Aho_corasick.pattern t m.pattern.

Building

val build : ?ignore_case:bool -> string list -> t
val pattern_count : t -> int
val pattern : t -> int -> string

Build once and keep the result. The value is immutable, so it can be a module-level let constructed at start-up from a configuration file and then shared by every request handler. 

let scanner = lazy (Aho_corasick.build (load_signatures ()))

build raises Invalid_argument on an empty pattern; an empty list is fine and yields an automaton that matches nothing, which is the right thing when a signature file turns out to be empty.

Searching

The five ways to ask
Function Returns Use when
find_all t s match_ list, every occurrence You want them all and the input fits in memory.
find_iter t s match_ Seq.t, the same, lazily You may stop early, or want to avoid the list.
find_leftmost_longest t s match_ list, non-overlapping You are going to cut, highlight or replace.
mem t s bool A yes or no is the whole answer.
replace_all t ~f s string Redaction, substitution, templating.

find_iter is genuinely lazy: it advances the automaton only as far as the consumer asks. Stopping after the first element of find_iter t "she........................." reads three bytes of the twenty-eight. 

(* first match only, without scanning the rest *)
match Aho_corasick.find_iter t input () with
| Seq.Cons (m, _) -> Some m
| Seq.Nil -> None

Streaming

module Stream : sig
  type state
  val start : t -> state
  val feed : t -> state -> string -> state * match_ list
  val feed_nonoverlapping : t -> state -> string -> state * match_ list
  val pos : state -> int

  module Leftmost_longest : sig
    type state
    val start : t -> state
    val feed : t -> state -> string -> state * match_ list
    val flush : state -> match_ list
    val pos : state -> int
  end

  module Replace : sig
    type state
    val start : t -> f:(match_ -> string) -> state
    val feed : t -> state -> string -> state * string
    val flush : state -> string
    val pos : state -> int
  end
end

Every one of them takes the automaton, the state you got back last time, and the next chunk, and hands back a new state. Nothing is mutated, offsets are absolute across the whole stream, and no chunk is ever concatenated with another.

Which one to feed
Entry point Streams Needs flush
Stream.feed find_all no
Stream.feed_nonoverlapping the earliest-end rule, Rust's stream_find_iter no
Stream.Leftmost_longest find_leftmost_longest yes
Stream.Replace replace_all yes

Every match, as it completes

In this split the first feed reports nothing at all — no pattern has finished by the end of ush — and the second reports all three, each with the offset it would have had in a single-pass scan of ushers. That equality is the property the test suite generates over: any chunking, concatenated, equals the whole-input result. 

(* scan a channel line by line, never holding more than a line *)
let rec pump t st ic =
  match In_channel.input_line ic with
  | None -> Aho_corasick.Stream.pos st
  | Some line ->
    let st, matches = Aho_corasick.Stream.feed t st (line ^ "\n") in
    List.iter
      (fun (m : Aho_corasick.match_) ->
        Printf.printf "%d..%d %s\n" m.start m.stop (Aho_corasick.pattern t m.pattern))
      matches;
    pump t st ic

Stream.feed_nonoverlapping is the same call with the same state type and the same zero latency, reporting a non-overlapping subset instead. Pick one of the two per stream and stay with it: the restart-after-match discipline only makes sense applied to the whole stream.

Leftmost-longest, with bounded lookahead

Stream.Leftmost_longest streams the same selection find_leftmost_longest makes. It cannot always answer immediately — a longer match starting at or before a candidate may still be arriving — but the wait is bounded by the longest pattern, and it ends with flush. 

module L = Aho_corasick.Stream.Leftmost_longest

let st = L.start t                  (* patterns ["b"; "ba"] *)
let st, ms1 = L.feed t st "ab"      (* [] : b at 1..2 might still grow *)
let st, ms2 = L.feed t st "a"       (* ba 1..3 *)
let rest = L.flush st               (* [] *)

Redacting a stream

Stream.Replace is replace_all over chunks: each feed returns the next piece of output, holding back only bytes that could still turn out to be inside a match. 

module R = Aho_corasick.Stream.Replace

let st = R.start t ~f:(fun _ -> "[X]")   (* patterns ["sam"; "samwise"] *)
let st, o1 = R.feed t st "say samw"      (* "sa" *)
let st, o2 = R.feed t st "ise sam"       (* "y [X]" *)
let o3 = R.flush st                      (* " [X]" *)
(* o1 ^ o2 ^ o3 = "say [X] [X]" = replace_all t ~f "say samwise sam" *)

Note that samwise wins over sam across a chunk boundary: the first feed emits only sa, because everything after it could still be part of a longer match. This is what makes a log redactor safe to point at a socket — the whole input never has to exist at once, and no secret slips through because it happened to be split in half.

A state is immutable and small — the plain ones hold a node and a byte count; the lookahead ones additionally hold the candidates and held-back bytes inside the current window — so one per connection costs little, and a socket that goes away can simply have its state dropped.

Cost

With n the input length and m the number of matches
Operation Time Allocates
build O(total pattern length) The automaton, once.
find_all O(n + m) The whole list.
find_iter O(n + m) to exhaust One cell per match consumed.
find_leftmost_longest O(n + m log m) All m matches, then the selection.
mem O(n), stops at the first match Nothing.
replace_all O(n + m log m) The output buffer.
Stream.feed O(chunk + matches in chunk) The returned list; state is two integers.
Stream.feed_nonoverlapping O(chunk) The returned list; state is two integers.
Stream.Leftmost_longest.feed O(chunk + candidates in the window) The candidates inside one longest-pattern window.
Stream.Replace.feed the same, plus the output piece The same window, plus the bytes held back inside it.

The per-byte cost is a hash-table lookup for the transition, plus the failure links the automaton has to follow when a byte does not extend the current match. Those follows are bounded in total, not per byte: a byte can push the automaton one node deeper, and every failure step moves it strictly shallower, so a scan of n bytes takes at most n failure steps overall — amortised constant time per byte, whatever the pattern set.

Memory is proportional to the total length of the patterns: one hash-table entry per distinct trie edge, plus a handful of arrays indexed by node. Nothing scales with the input.

find_leftmost_longest is the one function that is not streaming-friendly by construction: it materialises every overlapping match before selecting between them, so on a pathological input — a dictionary of short patterns against a long text — m can be much larger than n. If that matters, find_iter and your own selection loop will use less memory.

Concurrency

t is immutable after build returns and holds no mutable state, so one automaton can be shared by any number of threads or OCaml 5 domains without locking. Stream.state is immutable too, and feed is a function of its arguments alone — two connections scanning with the same t cannot interfere with each other.

Recipes

Redact a dictionary of secrets from a log line

let scrub t line = Aho_corasick.replace_all t line ~f:(fun _ -> "[REDACTED]")

Leftmost-longest is what you want here: overlapping matches would replace the same bytes twice, and the longest secret wins where two share a prefix. For a log stream rather than a line, reach for Stream.Replace instead.

Reject a request as early as possible

if Aho_corasick.mem signatures body then reject () else accept ()

Count hits per pattern

let counts = Array.make (Aho_corasick.pattern_count t) 0 in
Seq.iter
  (fun (m : Aho_corasick.match_) -> counts.(m.pattern) <- counts.(m.pattern) + 1)
  (Aho_corasick.find_iter t input)

find_iter rather than find_all, so a body with a million hits does not become a million-element list first.
