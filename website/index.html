ocaml-aho-corasick

Search for many patterns at once, in a single left-to-right pass over the input, in time proportional to the input length plus the number of matches — and independent of how many patterns you are looking for. This is Aho and Corasick's 1975 algorithm, the workhorse behind secret scanners, WAF and IDS signature matching, log filtering and dictionary tagging. Pure OCaml, no dependencies.

There is one algorithm here and no protocol, so the only thing worth promising is exactness. Every rule about which matches are reported, in what order, and at which byte offsets is written down as a specification, checked on every CI run against an independent naive implementation, and lined up against what other Aho–Corasick libraries do so that porting a scanner to or from OCaml is a mechanical exercise rather than a guess.

  • Match spans are half-open byte offsets, start inclusive and stop exclusive — the same convention as the Rust aho-corasick crate's Span.
  • find_all is the standard, overlapping semantics; find_leftmost_longest is POSIX leftmost-longest. Both have a named counterpart elsewhere.
  • Report order is total and specified: by stop ascending, then longest first, then by pattern index.
  • A QCheck oracle compares find_all against a naive per-pattern scan over 1000 random pattern-set and input pairs, and chunked streaming against whole-input scanning over 500 more.

Pre-1.0, and not yet cross-tested against other implementations. The semantics below are specified and checked against an in-repository oracle; no differential harness runs this library against the Rust or Python ones. The conformance vectors are published so you can run that comparison yourself.

How it finds them all at once

The patterns are compiled into a trie: one node per distinct prefix, one edge per byte. Scanning would be easy if the input always followed a single branch, but it does not, so each node also carries a failure link to the node for the longest proper suffix of its prefix that is still a prefix of some pattern. When a byte does not continue the current branch, the automaton follows failure links instead of backing up in the input — which is why the input is read exactly once and never re-examined.

The one failure link drawn above is the interesting one. After the automaton reads s, h, e it is at the node for she and reports it; its failure link points at he, which is itself a pattern, so he is reported at the same input position. That chain of failure links through nodes that carry patterns — the dictionary-suffix chain — is what makes nested and overlapping matches come out for free. Every other failure link in this trie leads back to the root or to the single-byte nodes h and s.

Scanning ushers with this automaton produces exactly the three matches in the figure at the top of the page: she at 1..4, then he at 2..4 reported at the same input position, then hers at 2..6.

Install

opam install aho-corasick   # once released
opam pin add aho-corasick https://github.com/thevilledev/ocaml-aho-corasick.git

Nothing else is needed: the library is pure OCaml with an empty dependency list, and the test suite is the only thing that pulls in Alcotest and QCheck.

Quick start

Build the automaton once, then reuse it. The value is immutable and safe to share across threads and domains. 

let t = Aho_corasick.build [ "he"; "she"; "his"; "hers" ] in

Aho_corasick.find_all t "ushers"
(* [{pattern = 1; start = 1; stop = 4};   she
    {pattern = 0; start = 2; stop = 4};   he
    {pattern = 3; start = 2; stop = 6}]   hers *)

Non-overlapping selection and replacement use leftmost-longest, the semantics POSIX tools apply when they substitute: 

let t = Aho_corasick.build [ "cat"; "dog" ] in
Aho_corasick.replace_all t "cat and dog" ~f:(fun m -> Printf.sprintf "[%d]" m.pattern)
(* "[0] and [1]" *)

Input arriving in chunks is scanned without concatenating it, and matches that straddle a chunk boundary are still found, with offsets counted from the start of the stream: 

let st = Aho_corasick.Stream.start t
let st, ms1 = Aho_corasick.Stream.feed t st "ush"   (* ms1 = [], nothing has finished *)
let _st, ms2 = Aho_corasick.Stream.feed t st "ers"  (* she 1..4, he 2..4, hers 2..6 *)

The whole surface is eight functions and a submodule; see the API.

What this does not do for you

Regular expressions
Patterns are literal byte strings. No character classes, anchors, alternation or wildcards. If you need those, you need a regex engine, possibly with this as its literal prefilter.
Unicode
Matching is over bytes, and offsets are byte offsets. UTF-8 works, in that a UTF-8 pattern matches UTF-8 text, but ?ignore_case folds only ASCII A to Z, and there is no normalisation or grapheme awareness.
Leftmost-first semantics
There is no mode where the pattern given first wins over a longer one. If you are porting from something that behaves that way, read the semantics comparison first — this is the difference most likely to change your results.
Leftmost-longest over a stream
Choosing the longest match at a position needs the bytes that follow it, so Stream reports standard overlapping matches only. The Rust crate refuses the same combination, for the same reason.
Vectorised scanning
The inner loop is a plain hash-table transition per byte. There is no SIMD prefilter and no dense transition table; this is a correct, small, dependency-free implementation, not a race with Hyperscan.
